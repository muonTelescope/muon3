# ESP32-S3 acquisition prototype

This source targets the modular controller pin map in `hw/src/modular.ts`. It
loads the FPGA SRAM bitstream, checks the protocol, resets acquisition, drains
events independently of communications, and streams JSON lines over USB serial.
Optional Wi-Fi sends those same lines to a configured UDP collector. UDP is
unacknowledged; sequence numbers identify gaps and reordering. It is not a
guaranteed delivery transport.

**Bias stays off.** The firmware holds HV_EN low and the I2C mux in reset. It is
usable for digital-input bench acquisition after board bring-up, but is not yet a
complete optical detector application. Per-sensor bias, DAC threshold/baseline,
HV monitor calibration, temperature compensation and environmental sensors must
be implemented before enabling the SiPM supplies. There is deliberately no
generic sensor voltage preset. The retained S12572 sensors require their actual
operating-voltage labels and measured calibration.

ESP-IDF is not installed in this workspace's execution environment. The protocol
C decoder is tested against real simulated FPGA SPI traffic; this full embedded
application has not been compiled or run on a controller. Treat it as prototype
source, not a flashed or hardware-validated firmware release.

## Build

With ESP-IDF 5.x installed and exported:

```sh
sh hw/gateware/tests/run.sh
sh hw/gateware/build.sh
cd hw/firmware
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p PORT flash monitor
```

The firmware build refuses to proceed without the FPGA bitstream generated by
the timing-checked hardware build. That bitstream is embedded into the ESP32
application at configuration time. Configuration runs at a conservative bit-bang
clock; startup checks CDONE and protocol identity before allowing acquisition.
The reset and clock sequence follows the documented [Zephyr iCE40 driver
interface](https://docs.zephyrproject.org/latest/build/dts/api/bindings/fpga/lattice,ice40-fpga-bitbang.html):
at least 1.2 ms after configuration-reset release, eight leading clocks, and at
least 49 trailing clocks. Validate the physical configuration wiring on first
bring-up.

Wi-Fi is disabled by default and requires the explicit **verified 1.5 A bench
supply** override in menuconfig. This is a manual bring-up gate, not automatic
USB-C power negotiation. The PCB exposes CC1/CC2 on GPIO6/GPIO7; calibrated ADC
classification with error guards is still to be implemented. Do not infer supply
capacity from USB voltage alone. HV remains off regardless of this override.
Wi-Fi is also disabled when SSID is empty. Set SSID/password and the collector IPv4
address in **Muon3 prototype** under menuconfig. Generated `sdkconfig` is ignored
because it can contain credentials. Network credentials are never printed. This
prototype uses the classroom LAN, with no cloud service or account.

## Stream and losses

Each line contains `v`, `epoch`, `seq`, `type` (1 event, 2 status), `spi_hex`
(complete raw full-duplex SPI receive bytes), cumulative `software_drops`,
`udp_errors`, and `bias_enabled:false`. Status is sampled once per second.
`epoch` distinguishes acquisition runs within a boot using a monotonic startup
value; it is not globally unique across devices or power cycles. A deployment
collector must add station identity and boot/session identity.

The FPGA FIFO and 128-packet software queue have separate loss counters. A slow
USB consumer may stall the stream task; the acquisition task continues and counts
software queue drops. Wi-Fi delivery can be delayed by a stalled USB consumer in
this minimal implementation. No silent loss-free guarantee is made. Use a single
chosen transport during initial characterization, record raw status counters,
and inspect sequence gaps. FPGA and firmware counters wrap modulo 2^32.

Decode raw JSON from a saved USB log or collect UDP:

```sh
python3 hw/firmware/interface/decode_stream.py < station.jsonl
python3 hw/firmware/interface/decode_stream.py --udp 3333
```

The decoder preserves tick integers; use status `clock_hz` to convert to seconds.
Saturated widths have no reconstructed leading time. Boot log lines are skipped.
The raw SPI data remains the archival input. Protocol details and masks are in
`hw/gateware/README.md`.
